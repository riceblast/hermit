# DLC：VPN 热度输出补充

更新时间：2026-11-28。补充 [Patch 13](patch13-hotness.md) 之后的用户态改动；
本文替代原文的“仅一个 summary.tsv、九列、均值两位、比例一位”输出约定。
VPN 历史、统计范围、Idle 采样和 EWMA 计算仍沿用原文。

## 当前输出

`--out` 必须指定尚不存在的新目录，采样器在其中生成两个文件：

| 文件 | 列 |
| --- | --- |
| `summary.tsv` | `pid`、`EWMA_window`、`mean_hotness`、`pages`、`hot/cold` |
| `hot_distribute.tsv` | 前四列相同，随后为 `[0-0.2)`、`[0.2-0.4)`、`[0.4-0.6)`、`[0.6-0.8)`、`[0.8-1.0]` |

- `hot/cold` 合并在一个单元格中，形如 `2.0e5(20.00%)/8.0e5(80.00%)`。
  按未舍入的 `H ≥ mean` 分类为热，其余为冷。
- **精确均值为 0 时显示 `-/-`**，包括初始基线和空统计范围。
  仅因四位显示舍入成 `0.0000` 的正均值，仍输出冷热数量。
  这是显示约定，不改变 Client 中 `H=mean=0` 归热的规则。
- 均值保留 **4 位小数**；冷热比例和各分桶比例保留 **2 位小数**。
  五档单元格使用 `数量(比例%)`，最后一档包含 1.0。
- `pages`、冷热数量、分桶数量达到 **100000（六位数）**时使用科学计数法，
  尾数一位小数，指数无 `+` 和前导零：`100000 → 1.0e5`、`8300000 → 8.3e6`。
  更小的数量保持整数；PID、EWMA 编号不缩写。
- 表头和数据共用列宽并左对齐，仍以 TAB 分列；读取时对表头和数据字段均做 `strip()`。
- 两文件保留同一基线及每个完成 EWMA 组的对应行，组号和实际累计时间格式沿用 Patch 13。
  先写入并刷新分布，再写入并刷新 summary；分布写入失败时不追加该组 summary。

启动日志简化为：

```text
START a_bit_window=10.000 EWMA_window=2
```

不再显示 PID、publish、placement；参数控制的采样、发布和放置功能不受日志简化影响。
Client 1.19 的 `--placement` 用法见 [DLS 补充](patchDLS-vpn-placement.md)。

## 读取与验证边界

实现入口为 [rswap_hotness.c](../tools/rswap_hotness.c)。
[rswap_hotness_check.py](../tools/rswap_hotness_check.py)、
[rswap_analysis.py](../tools/rswap_analysis.py) 和实机验收读取代码已同步适配双文件、
表头填充、`-/-` 和科学计数法，并保留旧九列单文件日志的读取兼容性。

科学计数法后的数量是近似显示，不能直接 `int()`，也不能要求显示后的各项精确相加。
离线校验按舍入区间检查数量、比例与总量；实机验收用审计中的精确计数生成预期显示值后比对。
内部计数、Q32 热度、百分比计算和内核发布始终使用精确值。

构建：`make -C remoteswap/tools`。双文件及四位均值版本曾通过 **209 项本地回归**；
后续 `-/-`、列对齐和科学计数法修改按用户要求仅完成构建，未重跑测试。
这些显示修改不需要重编或重载 Client／内核。
